# 修复记录 — 单机基线-2：Redis 无认证 + 6379 端口全接口映射宿主机

- 问题编号：单机基线-2（P2）
- 修复日期：2026-10-15
- 关联场景报告：`../01-单机基线.md` 第三节
- 结论：**已修复并定向复现转绿**。测试数据未删除，redis AOF 数据卷保留。

## 一、现象

- bad-source.sh 首轮带 `REDISCLI_AUTH` 查询时报错：`AUTH failed: ERR AUTH <password> called without any password configured for the default user`。
- 复验无认证直查成功：`docker exec recmaestro-redis redis-cli ZCARD recmaestro:scheduled → 0`，即任何能触达 6379 的客户端无需认证即可执行命令。
- `deploy/docker-compose.yml` 中 redis 端口映射 `"6379:6379"` 绑定所有接口，暴露到宿主机/局域网。

## 二、根因

部署编排缺陷（非 Go 代码缺陷），三处叠加：

1. `deploy/docker-compose.yml`（修复前 :26）redis 服务 `command: ["redis-server", "--appendonly", "yes"]` **从未将 `REDIS_PASSWORD` 以 `--requirepass` 传给 redis-server**——即使 `.env` 填了 `REDIS_PASSWORD`，redis 侧也不要求认证（这正是带 AUTH 查询报 `called without any password configured` 的直接原因）。
2. `deploy/.env`（实际部署）未设置 `REDIS_PASSWORD` 键，且 `deploy/.env.example`（修复前 :8-9）注释写「Redis（无密码则留空）」，`REDIS_PASSWORD=` 留空，误导性地暗示无密码是合法形态。
3. redis 端口 `"6379:6379"` 全接口映射，叠加无认证放大暴露面。

Go 侧链路本身完备无缺陷：`internal/config/config.go:204-205` 早已支持 `REDIS_PASSWORD` 环境变量注入 `c.Redis.Password`，scheduler/worker 的 compose 环境也一直声明了 `REDIS_PASSWORD`——缺口只在 redis-server 一侧从未启用认证。

## 三、修复（deploy 最小改动）

`deploy/docker-compose.yml` redis 服务：

- `command` 追加 `--requirepass ${REDIS_PASSWORD:-redis123456}`，与 scheduler/worker 共用同一变量（默认值 `redis123456` 仅供本地开发，风格对齐 MYSQL 的 `:-root123456`）；
- 新增 `environment: REDIS_PASSWORD`（供 healthcheck 容器内引用，密码不落 healthcheck 命令文本）；
- `ports` 改为 `"127.0.0.1:6379:6379"`——栈内走服务名访问不受影响，仅保留本机回环运维路径；
- `healthcheck` 改为 `["CMD-SHELL", "redis-cli --no-auth-warning -a \"$$REDIS_PASSWORD\" ping | grep -q PONG"]`（启用 requirepass 后无认证 ping 恒返回 NOAUTH，旧探测会导致 redis 永远不 healthy、scheduler/worker 无法启动）。

scheduler/worker 服务：`REDIS_PASSWORD: ${REDIS_PASSWORD:-}` 默认值对齐为 `${REDIS_PASSWORD:-redis123456}`，保证 `.env` 未设时整栈开箱自洽。

`deploy/.env.example`：`REDIS_PASSWORD=redis123456`，注释改为「redis-server requirepass 即用此值；默认值仅供本地开发，生产务必改强密码」。

实际部署 `deploy/.env`（不入库）：追加 `openssl rand -hex 16` 生成的随机强密码（本文档不记录明文）。

## 四、验证（全部实际执行，WSL 内）

修复前复现：

```
$ docker exec recmaestro-redis redis-cli ZCARD recmaestro:scheduled   → 0（exit=0，无认证可执行命令）
$ docker exec -e REDISCLI_AUTH=whatever recmaestro-redis redis-cli ZCARD recmaestro:scheduled
  → AUTH failed: ERR AUTH <password> called without any password configured for the default user.
```

## 六、遗留与影响面提示

- mysql 的 `3306:3306` 仍为全接口映射，但 MySQL 有 root 密码保护，与本问题（无认证）性质不同，不在本单修复范围；生产就绪收尾时可一并评估收紧为回环绑定。
- 后续所有场景的 Redis 直查须带密码（`REDISCLI_AUTH` 或 `-a`，密码在 `deploy/.env`），无认证 docker exec 直查将返回 NOAUTH——复测脚本若有无认证直查需同步适配。
